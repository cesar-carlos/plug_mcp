# Tools MCP

Sem formulário do SDK e sem catálogo pronto. Token MCP **nunca** aparece no JSON da tool.

Consulta ao ERP: skill **publicada** define o escopo. Sem `sql`/`consultaSemantica`, executa a consulta exemplo. Com `sql`, a IA escreve SELECT no dialeto, validado contra o pacote (JOIN composto = conjunto de `pares[]`). Amostra estrutural: `inspecionar_consulta` (aceita validada / `rascunho_revalidacao` / publicada). Sem skill capaz: `SKILL_GAP`. Skill em treino que cobre a pergunta: `blockingReason SKILL_NOT_PUBLISHED` — não inventar tabela, coluna nem JOIN.

### Inspeção, deriva e flags

`inspecionar_consulta`: `acessoId` + `skillId`/`skillIds[]` + `finalidade` obrigatória + `sql?` + `params?` + `options.timeout_ms?` (teto 15 s). Sem `sql`, usa o `sqlModelo`. Teto rígido **100** linhas (`maxRowsApplied`). Sem cache, aprendizado ou paginação. Firebird: só a consulta exemplo (`inspecionar_consulta` sem `sql`); SQL livre → `DIALECT_UNSUPPORTED`. Segredo no SELECT é recusado (`PRIVACIDADE_NEGADA`) antes do hub; pessoal/sensível seguem e saem mascarados. Resposta: `columns`, `rows` já mascaradas, `columnsMetadata` (tipos/nulidade, também com zero linhas), `colunasMascaradas`, `truncated`, `sqlExecutado`, aviso `INSPECAO`. Auditoria grava `skill` + `finalidade` + número de colunas — não a amostra.

Mascaramento por linhagem (alias e expressão resolvem à coluna de origem; a mais restritiva vence):

| `sensibilidade` | Valor na resposta                                  |
| --------------- | -------------------------------------------------- |
| `livre`         | intacto                                            |
| `pessoal`       | `p_<hmac>` determinístico por sessão (`usuarioId`) |
| `sensivel`      | `[texto oculto]`                                   |
| `segredo`       | `[redacted]`                                       |

Não há opção para revelar segredo ou PII. Amostras não são persistidas.

`detectar_deriva_esquema`: `acessoId` + `tabela`. Compara a assinatura atual (colunas/tipos/relacionamentos mapeados) com `schema_snapshot`. Skills daquela tabela vão para `rascunho_revalidacao`, cache invalidado. **Não** reescreve schema, métrica nem JOIN.

`cancelar_operacao`: `operacaoId` devolvido pelo perfilamento/descoberta longa. `OPERACAO_CANCELADA` se a operação parar no meio.

Flags (default **ligado**; `false`/`0`/`no` desliga para rollback):

| Variável                      | Tools / caminho                     |
| ----------------------------- | ----------------------------------- |
| `MCP_INSPECTION_ENABLED`      | `inspecionar_consulta`              |
| `MCP_DISCOVERY_QUERY_ENABLED` | `descobrir_tabela`                  |
| `MCP_SEMANTIC_QUERY_ENABLED`  | `consultar_dados.consultaSemantica` |
| `MCP_SCHEMA_DRIFT_ENABLED`    | `detectar_deriva_esquema`           |

Tool desligada → `FEATURE_DESLIGADA` (não aparece em `tools/list` quando a flag já estava off no boot). Após deploy, o cliente MCP precisa **reconectar** — o catálogo `tools/list` pode estar cacheado.

HTTP (não são tools): `GET /health` → `status`, `service`, `version`, `sha` (GIT_SHA / SOURCE_COMMIT / GITHUB_SHA; `unknown` se o deploy não injetar), `buildTime`, `uptimeSec`. `GET /ready` → `SELECT 1` se há `DATABASE_URL`; senão `database: skipped`.

## Skills

`buscar_contexto` devolve `cobertura` (`completa` | `parcial` | `desconhecida`), `candidatos[]` (`termosEncontrados` / `termosAusentes`) e `consultaPermitida` só quando a cobertura é completa. Evidência é FTS/`ILIKE` (não RAG). Stem léxico une inflexão na cobertura (`titulo`/`titulos` pode autorizar); tokens extra na pergunta impedem `completa`. Match textual isolado não autoriza consulta. Cobertura de capacidade usa nome, slug, descrição, params e `metricasSaida` — **não** o `sqlModelo` nem `params.tipo`. Skills no envelope vêm como `{ id, slug, nome, status }`; `consultasAprendidas` trazem pergunta e ids — reuse o `id` em `obter_skill` (`consultasExemplo`). Se `consultaPermitida` e a skill tiver KPI de **agregação** (CAST/data não entram; IR só com alias medida no pacote; quantidade/`NroParc` fora salvo a pergunta falar de volume; score 0 sem IR omite), `consultaSemanticaSugerida` (KPI com maior overlap da pergunta; empate: IR, depois `definicao`, depois ordem; prefira `consultar_dados.consultaSemantica`). Sem overlay de medida, o esqueleto é omitido. Cobertura parcial: `obter_skill` + `validar_consulta`; `registrar_aprendizado tipo=sinonimo` se o usuário confirmar o termo. `SKILL_GAP` (cruzamento ou ausência) **não** pede sinônimo; o hint pede `listar_skills` e, se a pergunta parecer cruzamento, não cruzar skills sem JOIN publicado. Cobertura completa + skill publicada: `fluxoTreino` alinhado a `listar_skills` (`publicar_skill` feito). `SKILL_GAP` sem skill em andamento que cubra a pergunta **omite** `fluxoTreino` (não finge `criar_skill` pendente). Skill validada/rascunho que **cobre** a pergunta: `blockingReason: SKILL_NOT_PUBLISHED` e `nextAction` = `fluxoTreino.proximoPasso` — **não** é `SKILL_GAP`. `gap.code = SKILL_GAP` só quando não há skill capaz (publicada ou em treino): **não** chame `consultar_dados` ainda — se o hint pedir, chame `listar_skills` antes de desistir. `grafoParaTreino` só no fluxo de treino/gap. `skillsParaTreino` só as que cobrem a pergunta. `podeLiberar` exige perfil completo (tipo/cardinalidade quando há métrica/JOIN).

Cada tool de treino/skill devolve `fluxoTreino`: `passoAtual`, `proximoPasso` (pode ser `confirmar_relacionamento` / `mapear_tabela` / `listar_conflitos` quando publicar está bloqueado), `podeLiberar`, `pacoteMinimo` (orientação: uma tabela, colunas nomeadas, WHERE ou agregação, params com descrição; JOIN/KPI só se o usuário pedir — **não** afrouxa os gates) e passos (`feito` | `pendente` | `bloqueado`) com `hint`. Skill `validada` com perfil incompleto: `proximoPasso` nunca é `null`.

| `remover_skill`         | Apaga a skill (pacote e `sqlModelo`) deste `agentId`. Exige `confirmadoPeloUsuario: true`. Libera o slug. O grafo permanece; consultas aprendidas ficam com `skillId` nulo.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `listar_skills`         | Lista do `agentId`: `id`, `slug`, `nome`, `status`, `versao`, `motivoRevalidacao`, `podeLiberar`, `fluxoTreino`, `faltas[]` (`kind` inclui `kpi`, `alvo`, `nextAction` inclui `atualizar_skill` / `remover_relacionamento`). Falta `kind: kpi` de overlay financeiro não dispara em quantidade/parcelas. Sem `sqlModelo` — use `obter_skill` para o pacote.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `obter_skill`           | Pacote completo: escopo (`pares[]` nos JOINs), colunas (inclui `sensibilidade`), relacionamentos, regras/métricas, `consultasExemplo`, `guiaDialeto`, `escopoPadrao`, `faltas[]`. Aviso `PERFIL_AUSENTE` se tipo/formato/cardinalidade vazios ou incompatíveis. Skills com `escopo` vazio gravam o derivado do `sqlModelo` na primeira leitura.                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `expandir_escopo`       | Acrescenta tabelas já treinadas ao escopo. Exige `confirmadoPeloUsuario`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `salvar_consulta`       | Nomeia um SQL já comprovado (consulta aprendida). `consultar_dados` já grava o SQL; esta tool amarra a pergunta. Exige `confirmadoPeloUsuario`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| `registrar_aprendizado` | Obrigatório quando o usuário ensina regra/métrica/glossário/dicionário/sinônimo. Também em `consultar_dados.aprendizado[]`. `tipo=metrica` + `skillId` overlaya `definicao` no alias já existente em `metricasSaida` (alias inventado → `COLUNA_FORA_DO_ESCOPO`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Cada skill publicada também pode virar tool `skill_{slug}` se `MCP_SKILL_TOOLS_ENABLED=true` (default **desligado** — incham o contexto). Resources `skill://{agentId}/{slug}` (inclui `consultaSemantica`, `politicaConsulta`, `guiaDialeto`, avisos de perfil), `guia://paginacao`, `guia://dialeto/{dialeto}` e `obter_skill` permanecem. Prompts `pre_treino`, `consultar_com_skill` e `cadastrar_skill`.

## Consulta

`consultar_dados`: `acessoId` + `skillId` ou `skillIds[]` + `sql?` **ou** `consultaSemantica?` + **`pergunta` obrigatória** + `aprendizado[]?` + `params` + `options`. Sem `sql`/`consultaSemantica`, executa a consulta exemplo (`sqlModelo`) — só com uma skill. Se `buscar_contexto` devolveu `consultaSemanticaSugerida`, prefira `consultaSemantica` com esse esqueleto; SQL livre só se faltar elemento certificado. `consultaSemantica` (`versao: 1`, `metrica` = alias de `metricasSaida`, `dimensoes[]`, `filtros[{coluna,op,param}]`, `periodo[{coluna,de,ate}]`, `ordenacao[]`) só compila elementos certificados no pacote (flag `MCP_SEMANTIC_QUERY_ENABLED`); JOINs saem de `escopo.relacionamentos.pares[]`; qualificadores da `expr` que não são tabela do pacote (`cr` / `[cr]`) viram o nome físico da coluna; colunas são qualificadas (`tabela.coluna`) quando há mais de uma tabela; recorte `:empresa`/`:filial` entra se o acesso tiver escopo padrão; aviso `CONSULTA_SEMANTICA` lista o que entrou no SQL. Sucesso pode gravar o IR na skill se ainda estiver nulo. KPI declarado (`statusIncluidos`, `colunaData`) entra no compilador; SQL livre omisso gera aviso `KPI_DESALINHADO`. `politicaConsulta` da skill corta `max_rows`/tabelas/recorte temporal (`CONSULTA_ORCAMENTO`) antes do hub. Projeção de `segredo` (sempre, inclusive `MAX`/`MIN`/`SUM`) ou de `pessoal` (exceto `COUNT`) → `PRIVACIDADE_NEGADA` antes do hub. JOIN `N:N` ou cardinalidade ausente no recorte (AST ∩ `pares[]`, com métrica/`papel=medida` ou fallback `valor`/`saldo`) bloqueia agregação financeira (`FANOUT_NAO_DECLARADO`) também no `sqlModelo`. O validador casa o **conjunto** de igualdades de um JOIN (`pares[]`); se o pacote tem JOIN composto (`pares.length > 1`), o `ON` incompleto é recusado — fallback v1 de pares isolados só quando não há composto. Com mais de uma skill, `sql` é obrigatório (união dos escopos; conflito de params → `MULTI_SKILL_PARAMS`). Com `sql`, valida contra a união dos escopos publicados (tabela, coluna, JOIN, UNION/subquery) e executa no dialeto do acesso. Firebird: só consulta exemplo (`consultar_dados` / `inspecionar_consulta` sem `sql`), sem paginação gerenciada. Autorização = `client_token`. Params no fio são `:nome` (`@nome` no SQL é reescrito). Params `obrigatorio=false` ausentes viram `null`. Tipos: `string` / `number` / `integer` / `decimal` (string) / `date` / `datetime` / `boolean`. Listas/`IN`: `IN (:nome)` com array em `params` é expandido para um placeholder por valor (lista vazia → `VALIDATION_ERROR`); ou um placeholder por item já no SQL. Options: `max_rows`, `page`, `page_size`, `timeout_ms`. `page` e `page_size` só valem juntos (`page_size <= max_rows`): exigem `ORDER BY` no SELECT externo e recusam `TOP`/`LIMIT`. Sem metadata de paginação do agente → `METADATA_CONTRATO`. Defaults de empresa/filial do acesso são imutáveis.

SQL que o agente não classifica volta `INVALID_SQL` (não `ACCESS_REVOKED`); o hint cita as tabelas enviadas e o dialeto. Não trate como token revogado nem como “MCP mandou SELECT 1”. SQL Server **1033** no wrap de paginação gerenciada (`options.page`) também vira `INVALID_SQL` (não `PLUG_SERVER_ERROR`): repita **sem** `page`, com `TOP n` + `ORDER BY` (`guia://dialeto/mssql`). Não acrescente `OFFSET`/`FETCH` junto com `page`. `validar_consulta` já passa neste SQL.

Comparação de período: a IA escreve o SQL no escopo (params de data `:dataInicio`/`:dataFim` ou `OVER`/`LAG`). `consultar_dados` grava o que funcionou; `salvar_consulta` nomeia o exemplo se o usuário quiser. `buscar_contexto` pede para reutilizar `consultasAprendidas[].id` em `obter_skill.consultasExemplo`.

**Aprendizado (sempre):** o servidor grava o SQL que funcionou em `consulta_aprendida` associado a **todas** as `skillIds` usadas e devolve `aprendizadoGravado`. `pergunta` é obrigatória. Regras/dicionário/sinônimo: `aprendizado[]` na mesma chamada ou a tool `registrar_aprendizado` (dicionário exige tabela+coluna; tabela inexistente não vira global). `salvar_consulta` (com confirmação) nomeia um exemplo curado. `buscar_contexto` devolve as **perguntas** e `id` de `consultasAprendidas` (status `ativa`); o SQL está em `obter_skill`.

Empresa/filial default (`atualizar_escopo_padrao`) é filtro obrigatório quando essas colunas existem nas tabelas consultadas. `avisos` de `REGRA`/`METRICA` da `skillId` da chamada; se a nota tem `tabelaId`, a tabela tem de estar no SQL (teto de 3 `REGRA` por overlap com tabelas/aliases do SELECT; globais de processo ficam em `obter_skill`). Resultado agregado pode ser servido do cache (`QUERY_CACHE_TTL_MS`, Redis se `REDIS_URL`; chave `mcp:query:{agentId}:{hash}` — deriva invalida só esse prefixo).

`validar_consulta`: dry-run de escopo + envelope vazio no ERP (sem ler dado). O wrap `_validacao` tira o `ORDER BY` **externo** (SQL Server 1033 em derived table); `ORDER BY` dentro de `OVER (...)` permanece. Placeholders ausentes ligam-se a `null`. Aviso `LITERAL_TEXTO` se houver literal de texto no WHERE/HAVING (não é erro). `GROUP BY` acima do teto (16 expressões) é `VALIDATION_ERROR`.

Resposta tabular: `columns`, `rows`, `rowCount`, `truncated` (teto `max_rows`, só no caminho sem página), `paginacao` (`page`, `pageSize`, `hasNextPage`, `hasPreviousPage` quando paginou), `maxRowsApplied`, `sqlExecutado` (SQL enviado ao hub, já com `:nome`), `paramsUsados`, `asOf` (timezone do acesso, senão UTC), `recorte`, `escopoAplicado`, `avisos`, `aprendizadoGravado`, `columnsMetadata` (`name` + `type`/`nullable`; o hub pode omitir tipo — o MCP preenche `null` ou o tipo do grafo, inclusive no alias de `column_ref`; CAST/agregação não copiam). Células string são truncadas. Execução bem-sucedida promove colunas e JOINs a `validado_execucao`. Escopo vazio da skill é persistido na primeira consulta.
