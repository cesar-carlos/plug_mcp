# Tools MCP

Sem formulário do SDK e sem catálogo pronto. Token MCP **nunca** aparece no JSON da tool.

Consulta ao ERP: skill **publicada** define o escopo. Sem `sql`, executa a consulta exemplo. Com `sql`, a IA escreve SELECT no dialeto, validado contra o pacote. Sem skill capaz, `SKILL_GAP` — não inventar tabela, coluna nem JOIN.

## Treino e schema

| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## Skills

`buscar_contexto` devolve `consultaPermitida` e `consultasAprendidas`. Se houver consultas aprendidas, o `hint` pede para **reutilizar esses SQLs**. Se `consultaPermitida` for `false`, vem `gap.code = SKILL_GAP`: **não** chame `consultar_dados`. Se houver rascunho/validada, o `gap.hint` pede para **continuar** o `fluxoTreino.proximoPasso`. Sem skill em andamento, oriente `treinar_com_sql` → `criar_skill` → descrever params → `validar_skill` → `publicar_skill` com `confirmadoPeloUsuario: true`. O grafo em `grafoParaTreino` é material de treino, não licença para inventar JOIN. Rascunhos/validadas vêm em `skillsParaTreino`. A busca casa também `sqlModelo`, nomes/descrições/`tipo` de `params` e sinônimos.

Cada tool de treino/skill devolve `fluxoTreino`: `passoAtual`, `proximoPasso`, `podeLiberar` e passos (`feito` | `pendente` | `bloqueado`) com `hint`.

| Tool                    | Função                                                                                                                                                                                                                                                                                                    |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `criar_skill`           | Nomeia um SQL já treinado. **Trava** se as tabelas do `sqlModelo` não estão no grafo. `params[{ nome, descricao, obrigatorio?, tipo? }]` descrevem placeholders (`tipo`: string/number/date/boolean; default string).                                                                                     |
| `atualizar_skill`       | Atualiza nome/descrição/SQL/`params`. Se o SQL mudar, as tabelas precisam estar no grafo e o status volta a rascunho. Patch só de nome/descrição/params **mantém** o status.                                                                                                                              |
| `validar_skill`         | Envelope vazio (sem ler dado). **Recusa** params sem `descricao`. Ausentes → `null`. Skill já publicada **permanece** publicada. `enriquecer=completo` perfila o `sqlModelo` (skills antigas ganham cardinalidade/tipo sem reescrever SQL).                                                               |
| `publicar_skill`        | **Libera** só com checklist completo **e** `confirmadoPeloUsuario: true`. Mostre o resumo no chat antes. Tool `skill_{slug}` (se `MCP_SKILL_TOOLS_ENABLED`).                                                                                                                                              |
| `remover_skill`         | Apaga a skill (pacote e `sqlModelo`) deste `agentId`. Exige `confirmadoPeloUsuario: true`. Libera o slug. O grafo permanece; consultas aprendidas ficam com `skillId` nulo.                                                                                                                               |
| `listar_skills`         | Lista skills do `agentId` do acesso.                                                                                                                                                                                                                                                                      |
| `obter_skill`           | Pacote completo: escopo, colunas, relacionamentos, regras/métricas, `consultasExemplo`, `guiaDialeto`, `escopoPadrao`. Aviso `PERFIL_AUSENTE` se tipo/formato/cardinalidade vazios (`validar_skill enriquecer=completo`). Skills com `escopo` vazio gravam o derivado do `sqlModelo` na primeira leitura. |
| `expandir_escopo`       | Acrescenta tabelas já treinadas ao escopo. Exige `confirmadoPeloUsuario`.                                                                                                                                                                                                                                 |
| `salvar_consulta`       | Nomeia um SQL já comprovado (consulta aprendida). `consultar_dados` já grava o SQL; esta tool amarra a pergunta. Exige `confirmadoPeloUsuario`.                                                                                                                                                           |
| `registrar_aprendizado` | Obrigatório quando o usuário ensina regra/métrica/glossário/dicionário/sinônimo. Também em `consultar_dados.aprendizado[]`.                                                                                                                                                                               |

Cada skill publicada também pode virar tool `skill_{slug}` se `MCP_SKILL_TOOLS_ENABLED=true` (default **desligado** — incham o contexto). Resources `skill://{agentId}/{slug}` e `obter_skill` permanecem. Prompts `pre_treino`, `consultar_com_skill` e `cadastrar_skill`.

## Consulta

`consultar_dados`: `acessoId` + `skillId` ou `skillIds[]` + `sql?` + `pergunta?` + `aprendizado[]?` + `params` + `options`. Sem `sql`, executa a consulta exemplo (`sqlModelo`). Com `sql`, valida contra a união dos escopos publicados (tabela, coluna, JOIN) e executa no dialeto do acesso. Firebird: só consulta exemplo. Autorização = `client_token`. Options: `max_rows`, `page`, `page_size`, `timeout_ms`. `page` exige `ORDER BY` no SQL (também no `sqlModelo`) e só vai ao plug junto com `page_size`.

SQL que o agente não classifica volta `INVALID_SQL` (não `ACCESS_REVOKED`); o hint cita as tabelas enviadas e o dialeto. Não trate como token revogado nem como “MCP mandou SELECT 1”.

Comparação de período: a IA escreve o SQL no escopo (params de data `:dataInicio`/`:dataFim` ou `OVER`/`LAG`). `consultar_dados` grava o que funcionou; `salvar_consulta` nomeia o exemplo se o usuário quiser. `buscar_contexto` pede para reutilizar `consultasAprendidas` nessas perguntas.

**Aprendizado (sempre):** o servidor grava o SQL que funcionou em `consulta_aprendida` e devolve `aprendizadoGravado`. Envie `pergunta` (a pergunta do usuário) para indexar. Sem ela, aviso `PERGUNTA_AUSENTE`. Regras/dicionário/sinônimo: `aprendizado[]` na mesma chamada ou a tool `registrar_aprendizado`. `salvar_consulta` (com confirmação) nomeia um exemplo curado. `buscar_contexto` devolve `consultasAprendidas`.

Empresa/filial default (`atualizar_escopo_padrao`) é filtro obrigatório quando essas colunas existem nas tabelas consultadas. Regras/métricas da skill entram em `avisos`. Resultado agregado pode ser servido do cache (`QUERY_CACHE_TTL_MS`, Redis se `REDIS_URL`).

`validar_consulta`: dry-run de escopo + envelope vazio no ERP (sem ler dado). Placeholders ausentes ligam-se a `null`. Aviso `LITERAL_TEXTO` se houver literal de texto no WHERE/HAVING (não é erro). `GROUP BY` acima do teto (16 expressões) é `VALIDATION_ERROR`.

Resposta tabular: `columns`, `rows`, `rowCount`, `truncated` (só se veio linha além do teto), `maxRowsApplied`, `sqlExecutado`, `paramsUsados`, `asOf` (timezone do acesso, senão UTC), `recorte`, `escopoAplicado`, `avisos`, `aprendizadoGravado`. Células string são truncadas. Execução bem-sucedida promove colunas e JOINs a `validado_execucao`. Escopo vazio da skill é persistido na primeira consulta.
