# Tools MCP

Sem formulário do SDK e sem catálogo pronto. Token MCP **nunca** aparece no JSON da tool.

Consulta ao ERP: skill **publicada** define o escopo. Sem `sql`/`consultaSemantica`, executa a consulta exemplo. Com `sql`, a IA escreve SELECT no dialeto, validado contra o pacote (JOIN composto = conjunto de `pares[]`). Identificar o GDBR do acesso (`verificar_acesso` / `listar_acessos` / `dialeto`) e emitir SQL compatível é **treino + IA** — o `plug_server` é hub (`sql.execute`, policy, PayloadFrame, timeouts) e **não** implementa linguagem SQL, rewrite de dialeto nem classificação de erro mssql/sybase/postgres/firebird; `source: sql_engine` vem do motor/GDBR via `plug_agente` — corrija no dialeto do pacote, não espere o hub reescrever. Skill treinada num dialeto não licencia `TOP`/`OFFSET` de outro GDBR. Amostra estrutural: `inspecionar_consulta` (aceita validada / `rascunho_revalidacao` / publicada). Sem skill capaz: `SKILL_GAP`. Skill em treino que cobre a pergunta: `blockingReason SKILL_NOT_PUBLISHED` — não inventar tabela, coluna nem JOIN. O `initialize.instructions` / prompt `pre_treino` posiciona a IA como especialista em SQL no pacote **daquele agentId**. O **papel** combina a **persona do acesso** (tom/uso) com as **skills publicadas** (pacote). SQL comum primeiro; persona depois; em conflito vale o pacote fail-closed. Sem Bearer: só o bloco SQL. Com Bearer e **um** acesso: anexa a persona **depois** do SQL. **Várias personas = vários acessos** (`adicionar_acesso`); um acesso = um chapéu — não concatenar; leia `listar_acessos` / `persona://{acessoId}` depois de escolher o `acessoId`. Sessão que começa com 1 acesso e ganha o 2º (`adicionar_acesso`) **mantém o chapéu 1** em `initialize.instructions` até reconectar; `pre_treino` relê o banco. Persona **não** recorta skills nem licencia tabela, coluna, JOIN ou `consultaPermitida`. Não inventar especialidade.

### Várias personas

**Várias personas = vários acessos** (`adicionar_acesso`). Um acesso = um chapéu. O trio usuário+`agentId`+`client_token` tem **uma** persona (`atualizar_persona`). O mesmo `agentId` compartilhado entre usuários MCP diferentes pode ter textos diferentes. Persona oriente tom/uso; **não** recorta skills nem licencia SQL. Resource: `persona://{acessoId}` (Bearer).

Sessão que começa com **1** acesso e ganha o 2º (`adicionar_acesso`) **mantém o chapéu 1** em `initialize.instructions` até reconectar — o host não atualiza o system prompt no meio da conexão. O prompt `pre_treino` relê o banco (N acessos: não concatena chapéus).

### Inspeção, deriva e flags

`inspecionar_consulta`: `acessoId` + `skillId`/`skillIds[]` opcional + `tabela?` + `finalidade` obrigatória + `sql?` + `params?` + `options.timeout_ms?` (teto 15 s). Sem `sql` nem `tabela`, usa o `sqlModelo` (exige `skillId`). `tabela` monta `SELECT TOP/LIMIT n *`. Teto rígido **100** linhas (`maxRowsApplied`). Allowlist: qualquer tabela de skill validada/publicada/`rascunho_revalidacao` do agente. Sem cache, `consulta_aprendida` ou paginação gerenciada. Firebird: só a consulta exemplo (`inspecionar_consulta` sem `sql`); SQL livre → `DIALECT_UNSUPPORTED`. Amostra **crua** (sem máscara de texto; `PRIVACIDADE_NEGADA` de projeção fica em `consultar_dados`). Célula binária não vai nas rows: stub `{ kind: "anexo", truncated: true }` **sem handle** + aviso `ANEXO` (inspeção não emite handle; handle legado não é exportável). Resposta: `columns`, `rows`, `columnsMetadata`, `colunasMascaradas` (vazio), `colunasNovasNoGrafo`, `truncated`, `sqlExecutado`, aviso `INSPECAO`. Auditoria grava `skill` + `finalidade` + número de colunas — não a amostra.

Mascaramento por linhagem em **`consultar_dados`** (alias e expressão resolvem à coluna de origem; a mais restritiva vence). Inspeção devolve amostra crua.

| `sensibilidade` | Valor na resposta                                  |
| --------------- | -------------------------------------------------- |
| `livre`         | intacto                                            |
| `pessoal`       | `p_<hmac>` determinístico por sessão (`usuarioId`) |
| `sensivel`      | `[texto oculto]`                                   |
| `segredo`       | `[redacted]`                                       |

Não há opção para revelar segredo ou PII. Amostras não são persistidas.

`detectar_deriva_esquema`: `acessoId` + `tabela`. Compara a assinatura atual (colunas/tipos/relacionamentos mapeados) com `schema_snapshot`. Skills daquela tabela vão para `rascunho_revalidacao`, cache invalidado. **Não** reescreve schema, métrica nem JOIN.

`cancelar_operacao`: `operacaoId` devolvido pelo perfilamento/descoberta longa. `OPERACAO_CANCELADA` se a operação parar no meio.

## Consulta

| Tool               | Função                                                                                                                                                                                                                                                                                      |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `consultar_dados`  | SELECT no pacote publicado (`skillIds` omitido = união das publicadas). `sql` **ou** `consultaSemantica` **ou** `consultaAprendidaId` **ou** consulta exemplo. `pergunta` obrigatória. Máscara por linhagem. Stub `kind: anexo` com handle. Firebird: só exemplo.                           |
| `validar_consulta` | Dry-run de escopo + envelope vazio no ERP. `skillId` omitido = união das publicadas. Aceita `options.page`+`page_size` (mesma regra de corte). Wrap `_validacao` tira `ORDER BY` externo (SQL Server 1033).                                                                                 |
| `exportar_anexo`   | Bearer; **não** no bootstrap. Converte 1 handle de `consultar_dados` (jpeg/png → `type: image`; PDF → `type: resource`). Mesmos portões. Inspeção **não** emite handle; handle legado → `MIDIA_ORIGEM_INVALIDA`. Pessoal/segredo → `PRIVACIDADE_NEGADA`. Não é OCR nem conversor universal. |

`consultar_dados`: `acessoId` + `skillId`/`skillIds[]` **opcional** (omitido = união das skills **publicadas** do `agentId`; se vierem, recortam) + `sql?` **ou** `consultaSemantica?` **ou** `consultaAprendidaId?` + **`pergunta` obrigatória** + `aprendizado[]?` + `params` + `options`. Sem `sql`/`consultaSemantica`/`consultaAprendidaId`, executa a consulta exemplo (`sqlModelo`) — só com **uma** skill âncora. `consultaAprendidaId` reusa o SELECT gravado (exclusivo com `sql` e IR). Envelope `skillIds` = skills cujas tabelas físicas estão no SQL (não a lista inteira de publicadas). Se `buscar_contexto` devolveu `consultaSemanticaSugerida`, prefira `consultaSemantica` com esse esqueleto; SQL livre só se faltar elemento certificado. `consultaSemantica` (`versao: 1`, `metrica` e/ou `metricas[]` = aliases de `metricasSaida`, `dimensoes[]`, `filtros[{coluna,op,param,param2?}]` com ops `=`/`!=`/`>`/`in`/`like`/`is_null`/`between`, `having[{metrica,op,param}]`, `periodo`, `ordenacao[]`, `limite` = TOP/LIMIT sem `options.page`; `limite` + `options.page`/`page_size` → `VALIDATION_ERROR`) só compila elementos certificados no pacote (flag `MCP_SEMANTIC_QUERY_ENABLED`); JOINs saem de `escopo.relacionamentos.pares[]` e honram `tipoJoin` (`LEFT JOIN` se left; `INNER JOIN` se inner/ausente); qualificadores da `expr` que não são tabela do pacote (`cr` / `[cr]`) viram o nome físico da coluna; colunas são qualificadas (`tabela.coluna`) quando há mais de uma tabela; recorte `:empresa`/`:filial` entra se o acesso tiver escopo padrão; aviso `CONSULTA_SEMANTICA` lista o que entrou no SQL. Sucesso pode gravar o IR na skill se ainda estiver nulo. KPI declarado (`statusIncluidos`, `colunaData`) entra no compilador; SQL livre omisso gera aviso `KPI_DESALINHADO`. `politicaConsulta` da skill corta `max_rows`/tabelas/recorte temporal (`CONSULTA_ORCAMENTO`) antes do hub. Projeção de `segredo` (sempre, inclusive `MAX`/`MIN`/`SUM`) ou de `pessoal` (exceto `COUNT`) → `PRIVACIDADE_NEGADA` antes do hub. JOIN `N:N` ou cardinalidade ausente no recorte (AST ∩ `pares[]`, com métrica/`papel=medida` ou fallback `valor`/`saldo`) bloqueia agregação financeira (`FANOUT_NAO_DECLARADO`) também no `sqlModelo`. O validador casa o **conjunto** de igualdades de um JOIN (`pares[]`); se o pacote tem JOIN composto (`pares.length > 1`), o `ON` incompleto é recusado — fallback v1 de pares isolados só quando não há composto. Com mais de uma skill, `sql` é obrigatório (união dos escopos; conflito de params → `MULTI_SKILL_PARAMS`). Com `sql`, valida contra a união dos escopos publicados (tabela, coluna, JOIN, UNION/subquery) e executa no dialeto do acesso. Firebird: só consulta exemplo (`consultar_dados` / `inspecionar_consulta` sem `sql`), sem paginação gerenciada. Autorização = `client_token`. Params no fio são `:nome` (`@nome` no SQL é reescrito). Params `obrigatorio=false` ausentes viram `null`. Tipos: `string` / `number` / `integer` / `decimal` (string) / `date` / `datetime` / `boolean`. Listas/`IN`: `IN (:nome)` com array em `params` é expandido para um placeholder por valor (lista vazia → `VALIDATION_ERROR`; teto **64** itens → `VALIDATION_ERROR` `source: mcp` / `stage: in_lista` — recorte a lista, **não** interpole literais). `validar_consulta` também expande antes do RPC. Options: `max_rows`, `page`, `page_size`, `timeout_ms`. `page` e `page_size` só valem juntos (`page_size <= max_rows`): exigem `ORDER BY` no SELECT externo e recusam `TOP`/`LIMIT`. Sem metadata de paginação do agente → `METADATA_CONTRATO`. Defaults de empresa/filial do acesso são imutáveis.

SQL que o agente não classifica volta `INVALID_SQL` (`source: sql_engine`, não `ACCESS_REVOKED`). `sql_engine` é o motor/GDBR via `plug_agente`, não uma camada de dialeto do `plug_server`. SQL Server **1033** ou **4104** no wrap gerenciado (`options.page`): `INVALID_SQL` — `nextAction: consultar_dados` (não `validar_consulta`); repita **sem** `page`, com `TOP n` (`guia://dialeto/mssql`). Não acrescente `OFFSET`/`FETCH` junto com `page`. O rewrite do wrap continua no `plug_agente`. Envelope `source`/`hint`: [error-mapping.md](error-mapping.md).

Comparação de período: a IA escreve o SQL no escopo (params de data `:dataInicio`/`:dataFim` ou `OVER`/`LAG`). `consultar_dados` grava o que funcionou; `salvar_consulta` nomeia o exemplo se o usuário quiser. `buscar_contexto` pede para reutilizar `consultasAprendidas[].id` em `obter_skill.consultasExemplo`.

**Aprendizado (sempre):** o servidor grava o SQL que funcionou em `consulta_aprendida` associado a **todas** as `skillIds` usadas e devolve `aprendizadoGravado`. `pergunta` é obrigatória. Regras/dicionário/sinônimo: `aprendizado[]` na mesma chamada ou a tool `registrar_aprendizado` (dicionário exige tabela+coluna; tabela inexistente não vira global). `salvar_consulta` (com confirmação) nomeia um exemplo curado. `buscar_contexto` devolve as **perguntas** e `id` de `consultasAprendidas` (status `ativa`); o SQL está em `obter_skill`. SQL recusado pelo validador/hub **não** é gravado. Correção ensinada pelo usuário: `registrar_aprendizado` / `aprendizado[]` / `salvar_consulta`. `SKILL_GAP` → `lacuna_consulta`. Como ler `source`: [error-mapping.md](error-mapping.md).

Empresa/filial default (`atualizar_escopo_padrao`) é filtro obrigatório quando essas colunas existem nas tabelas consultadas. `avisos` de `REGRA`/`METRICA` da `skillId` da chamada; se a nota tem `tabelaId`, a tabela tem de estar no SQL (teto de 3 `REGRA` por overlap com tabelas/aliases do SELECT; globais de processo ficam em `obter_skill`). Resultado agregado pode ser servido do cache (`QUERY_CACHE_TTL_MS`, Redis se `REDIS_URL`; chave `mcp:query:{agentId}:{hash}` — deriva invalida só esse prefixo). Resultado com stub de anexo **não** é cacheado.

`validar_consulta`: dry-run de escopo + envelope vazio no ERP (sem ler dado). `skillId` opcional: omitido usa a união das publicadas. Aceita `options.page` + `page_size` (mesma regra de `consultar_dados` / `exigirPaginacaoEstavel`): TOP/LIMIT/FETCH/FIRST no SELECT externo com página → `VALIDATION_ERROR` (página sem corte, ou consulta única com TOP sem `page`). Sem `page`, TOP no SQL continua consulta única. O wrap `_validacao` tira o `ORDER BY` **externo** (SQL Server 1033 em derived table); `ORDER BY` dentro de `OVER (...)` permanece. Placeholders ausentes ligam-se a `null`. Aviso `LITERAL_TEXTO` se houver literal de texto no WHERE/HAVING (não é erro). `GROUP BY` acima do teto (16 expressões) é `VALIDATION_ERROR`.

Resposta tabular: `columns`, `rows`, `rowCount`, `truncated` (teto `max_rows`, só no caminho sem página), `paginacao` (`page`, `pageSize`, `hasNextPage`, `hasPreviousPage` quando paginou), `maxRowsApplied`, `sqlExecutado` (SQL enviado ao hub, já com `:nome`), `paramsUsados`, `asOf` (timezone do acesso, senão UTC), `recorte`, `escopoAplicado`, `avisos`, `aprendizadoGravado`, `columnsMetadata` (`name` + `type`/`nullable`; o hub pode omitir tipo — o MCP preenche `null` ou o tipo do grafo, inclusive no alias de `column_ref`; CAST/agregação não copiam). Células string são truncadas em 2048 caracteres **depois** de extrair binário (e só se a célula for texto). Célula binária (base64 do `plug_agente`, `Buffer`/`Uint8Array` real, Buffer JSON ou array de bytes; tipos grafo `binario`/`image`/`blob`/`bytea`/`varbinary`) vira stub `{ kind: "anexo", bytes?, mimeHint?, handle?, truncated: true }` **sem** payload — aviso `ANEXO`. Tipo binário detecta sem piso de 96 chars (piso só no decode mínimo 8 B + magic **ou** tipo). Sem tipo e sem magic: zip/ole opaco **não** vaza 2048 chars de base64 (omite a célula). Não invente bytes. Texto curto e `[redacted]` não viram anexo. `Buffer` real não cai em `JSON.stringify` nas rows. Resultado com anexo **não** entra no cache Redis. Handle só de `consultar_dados` é exportável. Execução bem-sucedida promove colunas e JOINs a `validado_execucao`. Escopo vazio da skill é persistido na primeira consulta.

`exportar_anexo` (Bearer; **não** no bootstrap): `acessoId?` + `handle` + `mimeDestino?` (`image/jpeg` default, ou `image/png` / `application/pdf`). Mesmos portões de `consultar_dados` (JWT, policy, skill publicada). 1 anexo por chamada. `file-type` após decode; allowlist jpeg/png/gif/webp/bmp/tiff/pdf; recusa ole/zip/exe/svg. O mime pedido pela IA **não** autoriza o tipo de origem. jpeg/png: conteúdo MCP `type: image` + texto curto (mime, bytes, aviso de resize lado ≤1280). PDF: `type: resource` (não force image; PDF→jpeg recusado). `structuredContent` só metadados (sem blob). Handle HMAC+TTL (~15 min) + `usuarioId` (cap **64 por usuário**, FIFO; inspeção não faz `put`), Buffer só em memória (1 instância — restart perde). Handle expirado/de outro usuário/`acessoId`/de `inspecionar_consulta` (legado) → `MIDIA_ORIGEM_INVALIDA` (chame `consultar_dados` de novo; **não** reexecuta SQL). Pessoal/segredo → `PRIVACIDADE_NEGADA` (`nextAction` não é `inspecionar_consulta`). Foto `livre` de `consultar_dados` ok. Não é conversor universal nem OCR.
