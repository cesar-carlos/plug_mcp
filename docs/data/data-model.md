# Modelo de dados

Não há tabela de senha de conta MCP, cliente de Authorization Server nem catálogo pronto.

## Cofre

- `usuario_mcp`: `email_enc`, `email_hash`, `senha_enc`, `token_hash` (SHA-256 do token MCP), `token_expires_at` (opcional; TTL `MCP_TOKEN_TTL_DAYS`). Unique em `email_hash` e `token_hash`.
- `acesso`: `usuario_id`, `agent_id`, `dialeto`, `nome_amigavel`, `client_token_enc`, `client_token_hash`, `status_acesso`, `escopo_padrao` (JSON empresa/filial), `timezone`, `nome_persona` (curto, teto 80), `instrucoes_persona` (teto 4000). Unique `(usuario_id, agent_id, client_token_hash)`. Vários acessos do mesmo `agentId` são independentes (tokens/policies distintas); não há deduplicação automática. **Várias personas = vários acessos**; um acesso = um chapéu. Persona é tom/uso **neste trio** usuário+agentId+token — não no Agent do hub; o mesmo `agent_id` em usuários MCP diferentes pode ter textos diferentes. Não recorta skills; **não** licencia consulta. Backfill: colunas nulas (migration `0021_acesso_persona.sql`).

## Grafo (`agent_id`, compartilhado)

- `grafo_dialeto`: um dialeto por agente (primeiro escritor; `atualizar_dialeto` regrava).
- `grafo_lock`: lock de merge (`SELECT … FOR UPDATE`).
- `coluna_grafo`: além de tipo/descrição/dicionário, `papel` (`chave|dimensao|medida|codigo|data`), `formato` (`date`/`number`), `perfil` (JSON: min/max, nulos, distintos, `candidatosDicionario`) e `sensibilidade` (`livre|pessoal|sensivel|segredo`, default `livre`). Preenchido no treino/`validar_skill` `enriquecer=completo` (catálogo + MIN/MAX). Tipo físico **incompatível** (ex. uuid vs temporal) é substituído no merge mesmo com origem mais fraca; campos semânticos e `sensibilidade` confirmada permanecem. Classe gravada com `confirmar_coluna` + `confirmadoPeloUsuario` (origem `confirmado_usuario`) **não** é apagada pelo perfil (`validado_execucao`). `consultar_dados` mascara pela linhagem SQL (alias/expressão resolvem à coluna de origem); `inspecionar_consulta` devolve amostra crua.
- `relacionamento_grafo`: um JOIN = lista ordenada de pares + uma cardinalidade. Campos legados `coluna_origem`/`coluna_destino` guardam o primeiro par (compatibilidade). `pares_fingerprint` identifica o conjunto (e o inverso). Unique `(agent_id, origem, destino, fingerprint)`. `escopo_validacao` (JSON empresa/filial) registra o recorte em que a cardinalidade foi confirmada. JOIN composto **remove** fingerprints cujo conjunto de pares é subconjunto. `remover_relacionamento` apaga um fingerprint (grafo e, com `skillId`, o pacote). JOIN sem igualdade é recusado; CROSS JOIN **não** grava relacionamento.
- `relacionamento_grafo_par`: pares compostos (`ordem`, `coluna_origem`, `coluna_destino`). Migration `0014_relacionamento_composto.sql` faz backfill do par legado.
- `schema_snapshot`: última assinatura mapeada por `(agent_id, tabela_nome)`, no recorte das colunas do pacote (`validada`/`publicada`/`rascunho_revalidacao`). `detectar_deriva_esquema` compara e não repara schema; tipo compatível com o papel não rebaixa.
- Busca léxica (**não RAG** — migrations `0016_conhecimento_fts.sql` + `0017_fts_hardening.sql` + `0018_fts_rank_trgm.sql`): coluna gerada `search_tsv` em `tabela_grafo` (nome, descrição), `skill` (nome, slug, descrição, params, `metricasSaida` alias/definição/grão — não dump cru do JSON nem `sql_modelo`/`expr`), `anotacao_grafo` (título+texto), `consulta_aprendida` (**só** `pergunta`, status `ativa`). Pesos FTS em `mcp_skill_search_vec`: nome/slug **A**, descrição/params **B**, métricas **C**. Extensão `unaccent` via função IMMUTABLE `mcp_unaccent`; `search_path` fixo (`pg_catalog, public`). GIN composto `(agent_id, search_tsv)` com `btree_gin`. `pg_trgm` (GIN `gin_trgm_ops`) em `skill.nome`, `skill.slug` e `consulta_aprendida.pergunta` para o fallback `ILIKE` de identificador. Ranking SQL `ts_rank` chega ao score de `conhecimentos[]`; tsquery vazia cai só no `ILIKE`. Sinônimo resolve skill por id/slug/nome **sem** concatenar UUID na tsquery. **Não** se indexa SQL aprendido, linhas de ERP nem amostras de inspeção. O dicionário FTS é `portuguese` do Postgres; a cobertura JS usa o mesmo stem léxico (`stem-portugues.ts`) por conjunto, não substring. Stopwords de tokenização JS (`hoje`, `quanto`, `tente`, `fazer`, …) são as mesmas de `coberturaDeSkill`. Pergunta aprendida genérica (`consulta`/`tente`/`servidor`) não vira `consultasAprendidas` — a regra AND da cobertura não muda. O papel que corre `db:migrate` precisa de privilégio `CREATE EXTENSION` (`unaccent`, `btree_gin`, `pg_trgm`). Sem embeddings: a extensão `vector` de `0008` era ociosa; `0019_drop_unused_vector.sql` faz `DROP EXTENSION IF EXISTS vector` sem reescrever `0008`.
- Precedência: `validado_execucao` > `confirmado_usuario` > `inferido`. Empate de texto → `conflito`. Execução bem-sucedida de `consultar_dados` promove fatos usados a `validado_execucao`. Cardinalidade composta é perfilada no recorte empresa/filial aplicável.

## Skills e notas

- `skill`: `slug` unique por `agent_id` (rename em `atualizar_skill` exige confirmação), `sql_modelo` (consulta **exemplo**), `escopo` JSON (tabelas, `colunasPorTabela` físicas, relacionamentos com `pares[]` + `colunaOrigem`/`colunaDestino` legado, `graoPorTabela`/`graoResultado`, `metricasSaida` com campos opcionais de KPI `definicao`/`grao`/`dimensoesPermitidas`/`statusIncluidos`/`statusExcluidos`/`colunaData` — overlay fail-closed só em aliases já no pacote; `pacoteVersao` atual = **2**), `consulta_semantica` (IR opcional: métrica, dimensões, filtros, período, ordenação), `politica_consulta` (JSON: `maxRows`, `timeoutMs`, `exigirRecorteTemporal`, `maxTabelas`, `modoPreferencial`), `params`, `versao`, `pacote_versao`, `status` (`rascunho` | `validada` | `publicada` | `rascunho_revalidacao`), `motivo_revalidacao`, `autor_usuario_id` (quem treinou, **não** chave de partição). O pacote é do **agente** (`agent_id`); o usuário MCP autentica e treina via acesso. Não há skill de “papel”: o domínio está em nome/descrição/`metricasSaida`/regras; o chapéu de tom fica na **persona do acesso**. Vários `agentId` (`adicionar_acesso`) = vários papéis. Pacotes v1 (par único) continuam legíveis. Skill **publicada** é a autoridade de consulta. `despublicar_skill` rebaixa para `validada` sem apagar o pacote. O pacote sincroniza cardinalidade/tipo do grafo em criar/validar/mapear/confirmar/treino (`sincronizarEscopoComGrafo`). Cutover: `npm run db:backfill-escopo` reconstrói o pacote e rebaixa publicadas para revalidação. Migration `0015_politica_lacuna.sql`.
- `anotacao_grafo`: nota/glossário/regra/métrica (`tipo` inclui `regra` e `metrica`); `tabela_id` opcional; `skill_id` nullable. `skill_id=null` não é global silencioso — tabela inexistente é recusada. Detalhe da busca e do recorte de policy: FTS acima e `buscar_contexto` em [tools.md](../mcp/tools.md).
- `consulta_aprendida` + `consulta_aprendida_skill`: SQL que funcionou, associado a uma ou mais skills. Consultas sem associação não entram em todas as skills. Contrato de status e envelope: seção Aprendizado abaixo.

## Aprendizado (migrations `0012`, `0015`, `0020`)

- `consulta_aprendida`: SQL que funcionou (gravado automaticamente em `consultar_dados`), pergunta, contrato de params, contagem de execuções, `status` (`ativa` | `inativa`). Associação N:N em `consulta_aprendida_skill`. Ao remover a skill, os vínculos somem; o SQL histórico permanece no `agentId`. `obter_skill.pacote.consultasExemplo` devolve as da skill. `buscar_contexto` devolve só perguntas e `id` de consultas `ativa` (sem SQL); o SELECT está em `obter_skill`.
- `sinonimo`: termo → skill/alvo (`alvoId` = id, slug ou nome). `buscar_contexto` resolve a skill e une aos candidatos — **não** concatena UUID na tsquery. `remover_skill` apaga sinônimos cujo alvo é a skill.
- `lacuna_consulta`: pergunta que caiu em `SKILL_GAP` (`tipo=skill_gap`) ou contrato de tool ausente (`tipo=ferramenta`, JSON `contrato`). Unique `(agent_id, tipo, pergunta_chave)` (upsert). `status` `aberta` | `arquivada`: `buscar_contexto` arquiva `skill_gap` quando a pergunta passa a `SKILL_NOT_PUBLISHED` ou `consultaPermitida`. **Não** grava `skill_gap` se já houver skill publicada no `agentId` (a busca por termos não prova ausência — `listar_skills`). `listar_lacunas` default só abertas. Sem embeddings.

## Auditoria

- `audit_log`: tool, SQL enviado, sucesso, código, linhas, duração. Sem segredos nem amostras de inspeção. `buscar_contexto` grava tags de telemetria em `sql_enviado` (counts/enums, sem a pergunta). `listar_auditoria` devolve `telemetria` só nessa tool. `listar_metricas_agente` agrega por tool/código e o campo `busca` (`total`, `consultaPermitida`, `skillGap`, `skillNotPublished`, `slotNarrativa`). `inspecionar_consulta` grava só skill, finalidade e número de colunas.

Leitura do grafo é recortada em aplicação pela policy do `client_token` (`allTables` / `tables`). A escrita acumula para todos os acessos daquele `agentId`.
